### Introduction to Matrix Factorization and Dimensionality Reduction 
* Motivation and Intuition
    - A ratings matrix is an overfit representation of user preference and item descriptions
        - Our preferences aren't entirely the huge matrix of everything we interact with
        - ratings/ items overlap and could be represented by a common factor that represents many things 
    - huge matrix means tons of complexity and computation issues 
        * Difficult Compute 
        * Can get worse results at this granular level 
    - Higher level attributes of what users like are better representation of taste 

* Singular Value Decomposition (SVD)
    - Intuition: We are going to take the large matrix of all users x all items and instead reduce it to all users x taste dimensions

    - Mathematically, if we have a Rank R matrix:
        * m = users, n = items then: 
        * m x n = m x r (rank R called U), rxr (diagonal matrix called S), rxn (rank R called V')
        * THEN if we cut the diagonal matrix by rank K, apply that to U and V', multiply them back together we get a reduced dimension representation of user x items 

* SVD and Matrix Factorization Takeaways
    - Clever and useful approach
        - reduces problems of synonym and overfitting
        - computational advantages on run-time 
    - significant challenges in model building 
        - trouble for large models
    - SVD is growning in use but still not dominant in the field (old, at least 2017)

### Singular Value Decomposition 
Formal structure, $R$ = $P$ $\Sigma$ $Q^T$

$P$ is a dense matrix of user x features. 

$Q$ is a dense matrix of item x features. Transpose means it is flipped (features on rows and items on columns)
    - expreses how relevent each feature is to the item 

For example,
* A feature in $P$ indicates how relevant a preference is for a given user
* That same feature in $Q$ then indicates how much that preference fits for a given item

$\Sigma$ then is a matrix of weights
* feature x feature diagonal matrix 
*  "across the whole dataset, how important is this feature for predicting preference"

Next, we pick some optimal K in the diagonal matrix. This then truncates the matrix and $P$, $Q$ so that they're now a higher dimension representation of the original matrix! 

* This helps reduce noise and focus on the features most important for generating predictions and ratings. 

* Handling Missing Data
    - Formula assumes we have all values of $R$, but we don't or we would just use those! 
    - imputation (mean, normalize and then missing becomes zero) or ignore

* Adding new data 
    - Very fast and don't need retraining of the model! 
    - Folding in is a technique we can solve for new users

### Gradient Descent Techniques 
* Problems with SVD
    - Slow, computationally expensive
    - Require great care how missing data is dealt with 

* Truncated SVD 
    - best k-rank approximation
    - under global RMSE 
    - How can we find optimal k? 
        * Is there a way to search for matricies with the least error? 
    
* Gradient Descent
    - convex optimization method 
    - Make a guess, look at the error combined with the derivative (the gradient) of the error to identify how to improve our prediction. 
    - Benefits
        * Fast
        * Ignores missing data 

* Algorithm Structure 
    - initialize values to train (item/user feature vectors) to arbitrary starting point
        * non-zero, usually random
    - try to predict each rating in dataset 
    - use error and update rules to update values for next rating/sample
    - iterate until convergence 
        * fixed stopping point
        * early stopping once the change gets small 

    - Stochastic Gradient Descent 
        * We make changes after EVERY rating evaluation
        * Regular Gradient Descent evaluates changes but doesn't update until entire dataset looped over and evaluated 
    
### On Folding-In with Gradient Descent 
* Orthogonality of SVD matricies not guaranteed during gardient descent. 
    - However, in practice - especially with a sufficiently small learning rate - they may be orthogonal _enough_ that folding-in works with acceptable accuracy.

### Probablistic Matrix Factorization 
* Basic ideas of probabilistic modeling
    - ASSUME the data is generated by some random process (with known structure)
    - learn parameters that would generate data that looks like what we have

* Lets say we want to create an algorithm that calculates item popularity as a probability. 
    - Could start basic: total times item bought/ total items bought (globally) - P(i | u)
    - But if we want to personalize this per user - P(r_ui | u) we run into issues:
        * many, many parameters
        * We don't know user preference for every item 

* Probablistic LSA (Latent Semantic Analysis)
    - goal: compute P(i | u)
    - Decompose latent factors:
        - $P(i | u)$ = $\sum$ $P(i | z)$ $P(z | u)$
    - $P(z | u)$ user picks a random feature
    - $P(i | z)$ picks a random movie from the features 
    - User preference decomposed into feature preference (latent features, like SVD)
